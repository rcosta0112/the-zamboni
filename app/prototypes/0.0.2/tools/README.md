# Tools

> **[Agent note]** Every script run outside the browser, what it's for and where it's described. Each script's header comment has the details; this is the index. `npm run` commands are run in `app/`; `node tools/…` and `blender … tools/…` in this version's folder, `app/prototypes/0.0.2/` ("(project root)": in `The Zamboni/`, with the path `app/prototypes/0.0.2/tools/…`).

## Exporting to the game

| Command | Script | Does | Described in |
|---|---|---|---|
| `npm run export:ship` | [`export.mjs`](export.mjs) | The whole ship export in one go: Blender, textures capped at 512 px, dedup, Meshopt, into `public/test/zamboni-ship.glb` and `zamboni-ship-col.glb`, **through the gate**: taken only when nothing differs from the last taken export (objects, animations, bytes, a new `PERF:` / `NODES:` / `NOTE:` / `POSE:` line, any `STOP:` line), but for the exceptions (`FLAG:` lines); otherwise the summary lists every reason and the files wait in `.export/ship/out/`. After a taken change, the after-export check (dev server up). `EXPORT_BLEND=<file>` exports another file (a scratch copy). Nothing is saved to the `.blend` (Blender may be open). Raw files, baked images and Blender's log: `app/prototypes/0.0.2/.export/ship/` (not in git) | Here; [asset pipeline](../../../../doc/architecture/asset-pipeline.md#before-the-next-export) (what to check) |
| `npm run export:crew` | [`export.mjs`](export.mjs) | The same for the crew placed in the ship: `public/test/zamboni-crew.glb`. Their places, poses and actions only flag; a lost action or a place that makes no sense stops it | Same |
| `npm run export:accept -- <ship\|crew\|player>` | [`export.mjs`](export.mjs) | Takes the files of a stopped export into the game as the summary showed them (no Blender), then the after-export check. Refused if the `.blend` was saved since that export | [asset pipeline](../../../../doc/architecture/asset-pipeline.md#the-gate-2026-10-20-item-48) |
| (run by the two above) | [`export-ship.py`](export-ship.py) | The Blender side of the ship export: parts, props, light markers, doors, the collider. **What** it exports is the list [`ship-export-list.json`](ship-export-list.json) (every collection counts, switched on or not; `NOTE:` lines for what's listed and missing, or in the file and not listed); every tag is read from the reference file | Its header; [reference file](../../../../doc/architecture/asset-pipeline.md#the-ships-reference-file) |
| `npm run export:player` | [`export.mjs`](export.mjs) | The player's Dr. Green from the ship file's `Player` collection (with the jetpack and the hood's shape key; no binoculars), at the file's scale, with the ladder's climbing animation baked (IK solved) and where it starts tagged `climb`: `public/test/green-parka.glb`, not compressed (the game loads it without a Meshopt decoder) | Same; [interaction](../../../../doc/features/interaction.md#the-jetpack-rack) |
| (run by `export:crew`) | [`export-ship-crew.py`](export-ship-crew.py) | The Blender side of the crew export: Dr. Kaufman skinned with her action, the others as static poses, as placed (their heights relative to Dr. Green checked); a `CREW:` line each, `STOP:` lines for a missing action, a character at the origin, outside the ship, below their deck's floor, or two overlapping | Its header; [ship contents plan](../../../../doc/plans/features/ship-contents.md) |
| (imported by all three) | [`export_collections.py`](export_collections.py) | Switches the file's collections as [`export-collections.json`](export-collections.json) says (a new one stays off and is flagged), shows hidden objects the export needs, puts the file in object mode and at its start frame; all in memory | Its header; [asset pipeline](../../../../doc/architecture/asset-pipeline.md#before-the-next-export) (the table) |
| `npm run rest-poses [-- --accept "<name>"]` | [`rest_poses.py`](rest_poses.py) (run by `export.mjs`) | The moving parts' rest poses, [`rest-poses.json`](rest-poses.json) (local transform by name; one line each): compares the file with it (`POSE:` lines), or, with `--accept`, takes the file's pose of that part as its rest pose (a new part is added, a record with no part dropped; repeatable). Imported by the exports: the scene at its start frame (all three, through `export_collections.py`); the moving parts' actions dropped and each put at rest (ship). Nothing is saved to the `.blend` | Its header; [robust exports plan](../../../../doc/plans/features/robust-exports.md) |
| (imported by all three) | [`scale_check.py`](scale_check.py) | Stops the export (a `SCALE:` line) unless the player's armature is at scale 1 and 1.23 tall: the file is the game 1:1 | Its header; [asset pipeline](../../../../doc/architecture/asset-pipeline.md#export-proposed) |
| `blender -b "<file>" --python app/prototypes/0.0.2/tools/ship-export-list.py -- --out <json> [--everything]` (project root) | [`ship-export-list.py`](ship-export-list.py) | What the ship export took by its rules until 2026-10-19 (the collections switched on), as a list. Made `ship-export-list.json` from 1.19; with `--everything`, for comparing another file with the list | Its header |
| (imported by both) | [`bake_materials.py`](bake_materials.py) | Bakes to images what the glTF exporter can't follow in a material (ramps, mixes, procedural textures before the colour, glow or alpha); prints `NODES:` lines | Its header; [decision log](../../../../doc/decision-log.md), 2026-10-13 |
| (run by `export:player`) | [`export-crew-character.py`](export-crew-character.py) | One character from a `.blend` (the player's model, `green-parka.glb`): rest pose at the origin, modifiers applied keeping shape keys, at the file's scale | Its header; [prototype 01 plan](../../../../doc/plans/prototypes/01-walk.md) |
| `blender -b --python tools/export-part1-character.py` | [`export-part1-character.py`](export-part1-character.py) | Part 1's Dr. Green from its FBX, with her animations (`part1-dr-green.glb`) | Its header; [prototype 01 plan](../../../../doc/plans/prototypes/01-walk.md) |
| `node tools/encode-audio.mjs` | [`encode-audio.mjs`](encode-audio.mjs) | The audio masters → `public/test/audio/` (AAC, with ffmpeg); Part 1's soundtrack from Part 1's project. `--only <name>` encodes one file | [Audio](../../../../doc/architecture/audio.md); `public/test/audio/SOURCES.md` |
| `node tools/make-placeholder-sounds.mjs` | [`make-placeholder-sounds.mjs`](make-placeholder-sounds.mjs) | The interactions' placeholder sounds, made from tones and noise (the recipe is in the script), and single footsteps cut out of Part 1's two running loops; into `public/test/audio/`. `--steps` lists every step found. Also the start button's click (`ui_click`). `--only <name>` makes one of the made sounds and leaves the rest alone. Also the jetpack rack's two (`sfx_jetpack_take`, `sfx_jetpack_return`) | Its header; [plan](../../../../doc/plans/features/interaction-sounds.md) |

## Checking

| Command | Script | Does | Described in |
|---|---|---|---|
| `npm run smoke` | [`smoke-01.mjs`](smoke-01.mjs) | The whole scripted check of this version in headless Chrome: a `PASS` / `FAIL` line per check, about three and a half minutes. **Once, at the end of a session's changes** | [Prototype 01's README](../README.md#scripted-check) |
| `npm run see-through` | [`see-through-views.js`](see-through-views.js) (run by `probe-01.mjs`) | The check while the see-through rules are rebuilt (owner, 2026-10-14: instead of the smoke script after each change; the smoke script once, before the branch is merged). About 30 s: she stands in the cargo bay, engineering, the crew quarters and the cockpit; three screenshots each (camera high from two sides, and low) in `app/prototypes/0.0.2/.export/see-through/`; prints what's drawn | Its header |
| `npm run probe -- tools/hull-clipping.js` | [`hull-clipping.js`](hull-clipping.js) (run by `probe-01.mjs`) | Objects that reach into the hull's wall, between its two skins, worst first (for fixing in Blender). About 40 s. In the crew quarters everything counts (the hull has only its outer skin there) | Its header |
| `npm run probe -- tools/after-export.js` | [`after-export.js`](after-export.js) (run by `probe-01.mjs`; by the exports after a taken change) | The check after an export (about 30 s): every door opens and comes back to its rest pose; ten rays from outside meet the collider where they meet the drawn hull; the four crew in the ship, Dr. Kaufman on the couch; the ladder's foot clear; she walks from the cargo bay into engineering. One `PASS` / `FAIL` line each | Its header; [robust exports plan](../../../../doc/plans/features/robust-exports.md) |
| `npm run probe -- <file.js>` | [`probe-01.mjs`](probe-01.mjs) | One question to the running prototype (about 20 s): runs the file's code in the page and prints what it returns; `--shot <out.png>` saves a screenshot after it, `--shots <folder>` lets the file take several with `shot(name)`. It presses a key first (the sound comes on), then uses the start screen's button once it's there; `--stay` leaves the start screen up. For looking at one thing after a change, and for trying a check out before it goes into the smoke script | Its header |
| (used by both) | [`browser.mjs`](browser.mjs) | Starts headless Chrome and talks to it; uses the start screen's button (`useStartButton`) | Its header |
| `blender -b --python app/prototypes/0.0.2/tools/hang-props.py -- [--save]` (project root) | [`hang-props.py`](hang-props.py) | A record: the extinguisher clamps tagged `part`, the engineering cabinets' contents parented to them (2026-10-15). Run again, it reports 0 changes | Its header |
| `node tools/compare-glb.mjs <before> <after>` | [`compare-glb.mjs`](compare-glb.mjs) | What differs between two `.glb` files, object by object. Compares animations too (names, lengths, what they move). Run by the export commands (the gate). It counts only a node's own mesh: a door with something hanging on it shows 0 triangles | Its header |
